Security

What the application does with your secrets, stated so that it can be checked.

Randomness

Every password is drawn from the platform's cryptographic random source — java.security.SecureRandom on the desktop, crypto.getRandomValues in the browser — through rejection sampling, so every word and digit is equally likely. No seeded or pseudo-random generator is reachable from the generation path; the linter forbids rand and friends in source.

What leaves the device

Nothing you generate. The desktop application makes one optional network request — to check for a newer release on GitHub, only when you ask or have switched the start-up check on. The web app loads its own files and nothing else; once installed it works offline. There is no telemetry.

Clipboard and screen

Copy places the password on the clipboard; the desktop app clears it after 60 seconds if it still holds the password. The QR code is shown on demand and hides itself after 60 seconds: anyone who can see the screen can read it, and the application says so beside the code.

The name you enter

Used in memory to exclude words containing parts of it, as directory policies require, and to re-check the assembled password. Never stored, never sent.

Sealed seasonal effects (a disclosure)

Builds made with the eggs flag carry a small sealed table (eggs.sealed.edn) of purely cosmetic seasonal effects — for instance snow around Christmas. Each trigger is stored as a salted SHA-256 hash and each effect as an AES-GCM ciphertext under a key derived from the trigger itself, so the table reveals neither the dates nor the effects until a date matches. Date triggers are enumerable (366 guesses), so they are obscured rather than secret. The effects touch only the appearance of the window; the code that unlocks them never imports the generation engine. What is sealed is when an effect runs and with which parameters: the effect implementations themselves (a snowfall canvas, for instance) are ordinary readable code in the build, as any reviewer will see. In the web app, ?egg-date=MM-DD in the address previews the effect for a given date — a convenience for checking a seasonal look out of season, nothing more. Default builds omit the table entirely; a build says which it is in its build information. The mechanism lives in one namespace, pwgen.eggs, so an audit finds a documented feature rather than an unexplained blob.
